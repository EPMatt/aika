# Architecture

## Component boundaries

React and TypeScript own rendering, selection, drafts, gestures, and focus. Tauri 2 supplies native chrome/webviews and typed IPC into Rust. Radix handles dialog/popover focus; system fonts avoid network downloads. CSP restricts the renderer to local assets and IPC, with inline styles for positioning. Tokens, SQL, provider registration, and arbitrary network or shell operations are not renderer APIs.

Native flow is **React → typed client → CalendarService → ProviderRegistry / Repository → protocol adapters**. Register Local and Google once per provider type. The shared repository owns SQLite and session history; adapters own provider protocol details. Blocking persistence and provider work run off the UI thread, and network work releases service/database locks.

The browser explicitly uses an in-memory `PrototypeRepository` with fixtures. Native startup uses IPC and never seeds a user's database with those fixtures. Keeping this boundary explicit makes the preview useful without confusing it with native persistence or authentication.

## Shared Rust and WASM domain

`aika-domain` owns event/time contracts, validation, recurrence expansion, and pure mutation plans. Native Rust links it directly; browser preview uses WASM generated by `pnpm domain:build`. Accounts, HTTP, credentials, and repository orchestration stay in the native core. Rust contracts generate committed TypeScript declarations through `pnpm types:generate`, avoiding independently maintained IPC types.

Local gestures and editor/CLI mutations use the same checked domain operations. Views derive span clipping, overlap lanes, overflow, and 15-minute snapping rather than storing layout. Gesture previews are temporary; successful saves trigger fresh snapshots, and request versions discard stale reads. This keeps failed writes from replacing displayed committed data.

## Persistence

Bundled SQLite stores `calendar.sqlite3` beneath the OS application-data directory for `dev.projectcal.desktop`. The CLI defaults to that same database and can select an isolated path. Current schema v6 migrates older versions transactionally, preserving IDs, events/exceptions, calendar settings, and preferences. Newer schemas and open/migration failures return errors rather than resetting data.

Normalized event JSON is stored with indexed calendar/kind/start/end columns. This preserves the contract while making bounded overlap queries possible without parsing every payload. All-day dates and timed instants are queried separately. Preferences, visibility, and default selection persist independently of event undo. Data is protected by the OS account/filesystem; it is not application-encrypted.

## Time semantics

Timed events carry canonical UTC instants and an IANA source zone. All-day events carry calendar dates with exclusive ends. Overlap uses `start < range.end && end > range.start`; touching boundaries are excluded. Snapshot date ranges are bounded to 366 days, allowing elapsed-time differences around zone boundaries.

Rust is authoritative for local wall-clock resolution: nonexistent times fail; repeated input requires an explicit offset. Recurring timed starts preserve source-zone clock time and elapsed duration, skipping invalid generated starts/dates; ambiguous generated starts use the earlier offset, while an explicit seed offset is retained. Cancelled occurrences consume count; invalid starts do not. Local recurrence supports daily, weekly, monthly date/ordinal weekday, and yearly schedules, with checked occurrence/series/following changes.

Luxon handles renderer formatting/layout, with shared fixtures checking boundary semantics. Canonicalizing POSIX-style OS locales to BCP 47 avoids Intl failures. Date drops retain local time/duration; timed moves preserve elapsed duration; gaps/folds require explicit editor resolution.

## Concurrency and undo

A process-local mutex protects repository access and session history; renderer mutations queue in invocation order. SQLite transactions compare expected persisted event aggregates/calendar metadata before writing, so desktop/CLI races fail without replacing newer data. Lock contention waits up to five seconds. Snapshot refresh on focus preserves unsaved drafts; stale drafts must be reopened before saving.

Undo records successful event changes in memory and applies checked compensation, preserving unrelated changes. Scoped splits are one undoable action. Calendar deletion and preferences do not enter event history. Undo ends on restart and fails when compensation would overwrite an external change. Remote pending work and conflicts are durable even though undo history is not.

## Connected-calendar decisions

G01–G07 are accepted decisions. Account connection, incoming sync, and ordinary-event outgoing sync are implemented with automated fixtures. Existing live Google validation was confirmed by the user on 2026-10-19 without platform/client/revision evidence; installed-platform and new-feature acceptance remain separate; the [integration guide](integrations/google-calendar.md) describes current behavior. Compatible recurring creation, occurrence writes, series metadata edits and deletion are implemented in follow-on phase 02. Recoverable following splits remain phase 03 work.

### ADR G01: Provider types and account identities

Register one adapter per provider type and model accounts separately. Use stable internal UUIDs and account/calendar-scoped remote mappings; Google subject is identity and email is display metadata. Reconnection retains mappings and exclusions. This supports multiple accounts and colliding remote IDs without provider branches in views. The same shared calendar connected through two accounts has separate labelled identities.

### ADR G02: Shared repository and capabilities

Local data, remote caches, settings, and history share one repository. Service and renderer intersect provider, calendar, and event capabilities; backend enforcement remains authoritative. This avoids duplicate persistence and stops writable calendars from making restricted meetings or series editable. Accounts and capabilities enrich native contracts without adding network/storage responsibilities to the pure WASM domain.

### ADR G03: Cache-first durable synchronization

UI/CLI reads use SQLite. Supported remote mutations commit effective local state and durable outbox intent together, retaining remote shadows/revisions separately. Network requests run outside locks. Complete staged generations publish shadows, events, cursors, and coverage atomically; failed resync preserves useful cache and pending intent. This supports offline work and restart recovery. Renewable 90-second account leases plus owner/epoch checks fence competing workers and stale responses. Stable operation IDs and acknowledgement recovery handle uncertain writes; automated recovery evidence is not live-provider acceptance.

### ADR G04: Explicit conflicts and compensating undo

Keep both versions or deletion states, pause only the conflicting event, and offer **Keep local** / **Keep Google**. Checked remote revisions prevent silent replacement. Undo cancels never-attempted pending work or queues compensation with dependencies for attempted/in-flight/acknowledged work. Pending intent/conflicts survive restart. Disconnect and exclusion refuse unresolved work by default. Account management offers a checked, explicit discard-and-disconnect recovery: it restores the last known incoming versions, retires pending intent, and fences workers atomically before credential deletion. Already sent requests may still take effect remotely. Calendar removal offers a separate checked discard-and-remove flow scoped to one imported calendar. It retires that calendar’s intent, clears effective events/cursor/coverage, repairs the default, and fences the current account worker while leaving credentials and other calendars intact. Stable mappings and incoming shadows remain for explicit re-inclusion; discarded operations never replay.

### ADR G05: Backend authentication and credentials

Rust owns system-browser authorization with S256 PKCE, fresh state, a random-port one-use loopback callback, cancellation/timeout, identity verification, and refresh. Credentials stay in persistent OS stores: Keychain, Windows Credential Store, or Linux Secret Service, without plaintext/session-only fallback. IPC returns progress/metadata, never tokens. This keeps credentials out of the renderer. Missing public Desktop client configuration disables connection; locked/unavailable storage pauses remote access while local/cache reads remain usable.

### ADR G06: Selection and sync lifetime

Backend descriptors drive the provider picker. Discovery checks every eligible calendar before confirmation; selection is distinct from local visibility. Reconnection preserves exclusions and presentation overrides. After confirmation, reconciliation adds newly eligible calendars and respects exclusions. Sync runs while the desktop is open on startup, focus/resume, navigation, manual refresh, 60-second polling, and debounced writes. No server, webhook, or background daemon is introduced. CLI edits queue intent for a later desktop cycle; removing an imported calendar excludes it from aika without deleting it remotely.

### ADR G07: Recurrence compatibility and bounded fallback

Import masters/exceptions without date filters and normalize only proven equivalent rules. Preserve unsupported provider payloads and cache expanded instances for 12 months past and 24 ahead, extended by online navigation. Missing offline coverage is explicit, avoiding a false empty schedule. Imported recurrence is currently read-only. Intended compatible occurrence/series/following writes require equivalence tests and durable multi-request split recovery; a SQLite transaction cannot make separate remote requests atomic.

## Google follow-on decisions (2026-10-19)

G08–G13 are accepted design decisions for the follow-on sequence. Phase 01 implements the durable foundation; phase 02 enables the compatible recurring write subset described below. Following splits, account deletion, and meetings remain gated by subsequent phases. Existing live Google validation was confirmed by the user on 2026-10-19 without platform/client/revision evidence; this does not validate new features or every installed platform.

### ADR G08: Exact recurrence compatibility

Share the pure domain and compile Google rules in the backend only when exact representation is established. Bounded preview agreement is insufficient because divergence can occur outside the window. Initially allow proven all-day/UTC rules; retain regional-zone/DST and richer schedules as read-only projections. This amends G07's intended write path, preserving its import behavior. Reject unsupported intent before committing it; do not approximate provider schedules.

### ADR G09: Durable ordered operation groups

Extend the existing outbox with durable groups, ordered steps, persisted resource identities, and aggregate before/after snapshots for every affected series. Single-event operations migrate as singleton groups without changing their delivery protocol. Serialize overlapping groups against every member and retain the complete overlay and incoming shadows until completion or explicit resolution. SQLite cannot make HTTP atomic: recover uncertain requests before resend, resume forward after partial success, and never automatically roll back acknowledged steps. Count actions rather than requests. Cross-calendar groups are disallowed; remote moves remain unsupported. Unrelated resources continue after a group's permission/validation failure; authentication pauses the account.

### ADR G10: Scope-specific actions

Expose typed edit/delete scopes with disabled reasons from native contracts, intersected with provider/calendar/event capabilities and enforced in Rust. Keep legacy capability booleans for compatibility; they do not independently authorize a recurrence scope. Local recurrence retains its existing behavior. Phase 01 kept all Google recurring scopes disabled; phase 02 enables compatible occurrence and series scopes while following retains an explicit disabled reason. Prefer explicit restrictions over a single recurrence flag that cannot describe partial support.

### ADR G11: Explicit exception policy

Google master edits preserve exceptions; local planner reset semantics remain unchanged. Future Google structural edits must establish correspondence or fail. Following splits require confirmation of future-exception reset. Do not silently reuse the local reset planner. Phase 02 introduces an explicit policy contract; phase 03 implements recoverable splitting and checked compensation after reconciliation. Until then, grouped conflict resolution/undo must refuse operations requiring a recurrence replan.

### ADR G12: Durable account cleanup

Full deletion will use a persisted cleanup lifecycle, checked generations, and cross-process identity locking around credential writes/deletion (never HTTP). Delete credentials before transactional cache/account cleanup; retry store failures and startup interruptions, retaining only an opaque lifecycle tombstone. A database-only delete or best-effort store cleanup can resurrect credentials through late workers. This is a future phase; current disconnect and calendar exclusion retain their established meaning.

### ADR G13: Native meeting intent and notifications

Keep organizer, attendees, responses, and delivery policy in native durable contracts, outside the pure recurrence domain. Future applicable writes and compensation persist everyone/external-only/none (`all` by default), warning before silent delivery. Narrow conditional updates preserve unknown fields and other attendees; resolve the authenticated attendee natively. Email delivery cannot be exactly once or recalled by undo. Meeting writes remain disabled pending phases 05–06.

## Distribution and evidence

Both workflows build Linux x64 on Ubuntu 24.04, Windows x64 on Windows 2025, Apple Silicon on macOS 15, and Intel on macOS 15 Intel. Embedded native automation currently runs only on Linux in the check workflow. Builds/package inspection do not certify desktop installation, upgrades, trusted input, or accessibility. See [contribution checks](../CONTRIBUTING.md#checks) and [release acceptance](releases.md#acceptance-checklist).

Production omits the debug-only native driver, with a release compile guard. Packages are unsigned on Linux/Windows and ad-hoc signed, without notarization, on macOS. There is no automatic updater, analytics, or application server.

### Phase 02 implementation of G08–G11

The backend compiler maps unsplit all-day and whole-second UTC/Etc-UTC domain rules to one RRULE: daily, Monday-anchored weekly with optional weekdays, monthly by date, and yearly. INTERVAL and COUNT retain their domain meaning, including skipped invalid month/year dates. UNTIL maps an inclusive all-day date to a DATE boundary, or a UTC date to that day's fixed start clock. No bounded preview is used as the authorization test. Regional-zone/DST, ordinal-weekday, fractional-second UTC and segment rules fail before local intent commits. Unsupported imports retain their projections. Timed UNTIL imports are compatible only when their UTC limit clock exactly equals DTSTART's UTC clock. This further amends G07's former read-only import restriction without changing its fallback/coverage architecture.

An optional generated `ExceptionPolicy` makes preservation explicit. Native Google validation selects `preserve`, rejects reset requests, and the shared planner carries existing exceptions into master metadata edits. Local native mutations retain reset semantics and reject a preserve policy. Structural changes to existing Google schedules are conservatively blocked: the cache cannot establish correspondence for every remote exception. Changing one instance's time remains available. Narrow If-Match patches preserve recurrence and provider-only fields during metadata edits; attendee-bearing, special, locked and conference-bearing events remain read-only.

Occurrence steps keep full aggregate before/after payloads plus a series/original-start selector. Claim releases its SQLite transaction for adapter instance lookup, then rechecks the lease/epoch and operation before persisting the real resource identity and independent instance revision. Lookup compares editable before fields when no prior instance revision was captured; disagreement forces conflict. Binding survives retry/restart. Master revision dependencies reference preceding master steps explicitly; an interleaved occurrence acknowledgement never supplies a master ETag. Delivery checks the current compatible master and selected instance identity, and uses conditional PATCH (`status=cancelled` or `confirmed`) on the actual instance. Standalone projected instances never gain ordinary-write capabilities. Provider observations map to the child resource, while completion/conflict review rebuilds the master aggregate with all retained child observations.

Unattempted actions cancel through existing group-aware undo. Attempted single-resource undo waits behind predecessor reconciliation and queues checked compensation. Recreating a delivered deletion reserves a fresh master ID and restores its exceptions through ordered, individually resolved instance steps in one group; partial progress retains the full overlay and resumes forward. This is deterministic restoration, not a following split/replanner. A blocked restore can be retried or discarded; delivered steps remain effective. Keep local can requeue a single occurrence or metadata change from checked observed aggregates. Combined master/exception or multiple-exception replans and attempted multi-step undo still return a recovery restriction pending phase 03. No schema migration is needed beyond v6; pre-phase-02 Google capabilities are re-evaluated from backend shadows.
