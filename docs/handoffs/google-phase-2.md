## Delivered behavior and interfaces

- **Providers and sessions:** Local and Google descriptors appear in production. Missing `AIKA_GOOGLE_CLIENT_ID` disables Google with an explanation; optional `AIKA_GOOGLE_CLIENT_SECRET` is supplied when present in Google's Desktop app client configuration. These are public desktop-client settings, read from the native process environment; never use renderer `VITE_` settings. Only fixed Google authorization/API URLs are opened/called. User tokens, codes, verifiers, and raw failure bodies never cross IPC or enter SQLite/logs.
- **Connection:** start/status/cancel use an opaque session UUID; credential and browser work remains outside repository locks. Matching state and exactly one code are required; wrong-state/malformed callbacks cannot consume the listener. Denial, cancellation, timeout, secure-store errors, network/authentication/permission errors have redacted recovery messages. A late connection-start response after closing the dialog is cancelled. Completed-session polling cannot reconnect an account after disconnecting it.
- **Accounts:** stable Google subject identifies an account; verified email is display metadata. Credential keys scope provider/subject, independently of SQLite account UUIDs. Reconnecting updates the same account and leaves its calendar IDs/selections intact. Multiple Google accounts can be connected sequentially. A locked/unavailable store stops remote access without plaintext or session-only fallback; Local and cached reads remain independent.
- **Discovery/selection:** every page is collected before confirmation, with hidden entries included. Names/colors/account/access status and disabled explanations are presented. New eligible entries start checked; previous explicit exclusions remain unchecked. Discovery results remain ephemeral until a one-use checked confirmation. Changing selection through another service/CLI invalidates a stale discovery. Selection and visibility remain independent; existing name/color/description/visibility overrides are preserved. Pending operations block exclusion atomically. Permission loss marks an existing calendar inactive while preserving its selection intent/cache; newly inaccessible entries are not persisted as exclusions.
- **IPC:** `list_providers`, `start_connection`, `connection_status`, `cancel_connection`, `discover_calendars`, `commit_calendar_selection`, and `disconnect_account`. Accounts arrive through the existing collection snapshot. No token, arbitrary URL, SQL, provider-registration, or raw import-metadata IPC was introduced. Backend-only provider methods accept/return protocol identities rather than owning application persistence.
- **Contracts/storage:** generated `ConnectionProgress`, `ConnectionSession`, `DiscoveredCalendar`, and `CalendarDiscovery` extend the native contract. Domain/WASM event contracts are unchanged. Schema remains v4; its existing account/selection/active/capability fields suffice. Default and visibility behavior and session undo remain compatible. Google adapter capabilities intersect stored permissions and prohibit all event mutations/default creation.
