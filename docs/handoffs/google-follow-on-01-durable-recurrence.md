## Implemented behavior and decisions

[Architecture decisions G08–G13](../architecture.md#google-follow-on-decisions-2026-10-19) record rationale, alternatives, compatibility, failure behavior, and the explicit amendment to G07. G01–G07 retain their history. Only the phase 01 foundation is implemented; the recurrence compiler, exception policy, splits, full account deletion, meeting writes, and RSVP remain future work.

- One action owns a durable group, ordered steps, and complete per-series before/after snapshots. All create resource identities are reserved when intent is persisted; operation IDs and attempted identities survive restart. Later edits following delete/undo/recreate use the newly reserved identity.
- Overlapping groups serialize against every affected series. An acknowledged member keeps its local overlay while any sibling remains unresolved; incoming shadows continue updating. Completing a group publishes observed members together, preserving later pending overlays.
- Pending and attempted reviews count actions once, including successful siblings of unfinished groups. Permission/validation failures block their group; unrelated work continues. Authentication and unavailable credentials retain account-level pausing. Uncertain ordinary requests reconcile through the existing GET/operation-marker/conditional-revision protocol before resend.
- Retry, conflict review, calendar discard, and disconnect account for the entire group. Reviews cover acknowledged step progress, aggregate snapshots, local exceptions, and incoming versions. Keep Google captures and retires the transitive component of overlapping pending groups, then restores observed provider state. Calendar/account discard fences late workers and leaves successful remote steps effective.
- Complete wholly unattempted groups can be undone atomically. Partial undo is refused. Attempted multi-step undo and Keep local for multi-step groups return `groupRecoveryRequired`; checked recurrence replanning/compensation belongs to phase 03. Existing ordinary-event compensation remains available.
- Native `EventActions`/`ScopeAvailability` contracts expose typed edit/delete scopes with disabled reasons. Rust enforces them, renderer controls consume them, and `aika-cli events actions ID` prints them as JSON. Every Google recurring scope stays disabled; local recurrence semantics are unchanged.
- Backend instance preflight uses Google's [instances endpoint](https://developers.google.com/workspace/calendar/api/v3/reference/events/instances) and matches series plus canonical `originalStartTime`, including moved/cancelled results. Pagination is checked; missing, ambiguous, or repeated results fail. No instance IDs are manufactured. Occurrence-selector steps are explicitly blocked in phase 01; phase 02 must bind resolved identities and supply recurrence delivery before enabling them.

## Schema and API compatibility

Schema v6 adds `operation_groups`, `operation_group_series`, and `active_group_series`; outbox rows gain `group_id`, `step_index`, `resource_id`, `series_remote_id`, and `original_start`. Group/account/calendar scope is checked on insertion and outbox reassignment. Unique group/step ordering prevents duplicate positions. Existing outbox rows become singleton groups in their original order, retaining dependencies, payloads, states, attempts, retry deadlines, and acknowledgements. Migration runs in the existing immediate transaction; failure rolls back schema and data. Downgrading a v6 database to an older application is unsupported and rejected by its schema guard.

Native collection snapshots add `eventActions`; conflicts add a generated optional `groupRevision` review fingerprint. Native-produced conflict reviews always include this fingerprint; stale or incomplete reviews fail comparison. Types are generated from Rust. Existing stored capabilities need no JSON migration. Browser preview supplies its existing local behavior; native group persistence and Google authentication are never simulated as live acceptance.

## Recovery and remaining restrictions

On restart, the account lease/epoch guard rejects old owners; unfinished ordered steps reconcile uncertain results using their persisted operation/resource identities. Earlier successful steps remain acknowledged; the complete overlay stays until completion or explicit resolution. A blocked/conflicted sibling prevents the rest of its group from advancing. Explicit discard restores retained incoming observations and retires the action; it does not reverse delivered Google changes. No automatic rollback of successful remote requests is introduced.

The internal grouped machinery is exercised by fixtures and the repository mutation path. Product Google writes remain ordinary-event-only. Phase 02 must implement an exact recurrence compiler, explicit exception policy, resolved-instance binding, narrow conditional recurrence delivery, and renderer/CLI scoped operations before removing the write gates. Phase 03 supplies following splits, partial-result UI, checked Keep local replanning, and compensation after attempted multi-step work. Cross-calendar groups, remote moves, special event types, conference creation, and meeting writes remain unsupported.

Carry forward the agreed defaults: start writes with proven all-day/UTC recurrence; keep regional-zone/DST and richer rules read-only; preserve Google whole-series exceptions while retaining local exception-reset semantics; separately confirm future-exception reset for following splits; support organizing and responding to meetings in later phases; persist everyone/external-only/none notifications with everyone as default. Existing live Google validation was confirmed by the user on 2026-10-19 without platform/client/revision details, and does not establish acceptance for new features or every installed platform. Source-zone/DST write expansion requires separate equivalence evidence.
