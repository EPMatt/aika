## Implemented behavior and architecture

[Decisions G08–G11](../architecture.md#phase-02-implementation-of-g08g11) now have a concrete phase 02 implementation. G01–G07 retain their history; the documented G07 amendment enables only the proven compatible write subset. G12–G13 remain future work.

- The native compiler emits one exact RRULE for unsplit all-day or whole-second UTC/Etc-UTC daily, weekly with Monday week phase/optional weekdays, monthly-by-date and yearly patterns. Intervals, counts and inclusive end dates map directly; skipped invalid month/year dates do not consume count. UTC UNTIL uses the final date's fixed start clock. Equivalence rests on field/clock correspondence, with supplementary round-trip fixtures; bounded preview agreement alone never authorizes a write. Regional/DST, ordinal-weekday, fractional-second UTC and segment rules fail before local intent commits.
- Occurrence edits, cancellation and restoration resolve Google's actual instance identity by master plus canonical original start, including moved/cancelled instances. No instance IDs are manufactured. Claim releases its SQLite transaction for lookup, then fences the worker and rechecks the operation before persisting resource identity and the independent instance revision. Unobserved before-field disagreement produces a conflict rather than overwriting Google. Interleaved master/occurrence steps retain resource-specific revision dependencies, including a durable internal predecessor reference until its acknowledgement is available. Invalid/missing identities or revisions block the group; unrelated events continue.
- Delivery checks the compatible master, instance identity and editable fields, then conditionally PATCHes the actual instance. Cancellation uses `status=cancelled`; restoration uses `confirmed`. Persisted operation markers, IDs and revisions recover uncertain responses before resending. A missing child creates a child observation/conflict, never a master tombstone.
- Whole-series deletion and master metadata edits are enabled. Native Google validation selects the explicit preserve policy and rejects reset requests. Metadata patches omit recurrence, time and unrelated provider fields. Existing exception edits/cancellations survive. Structural edits to existing schedules remain conservatively blocked: the cache cannot establish correspondence for every remote exception. The renderer locks these schedule fields and explains the restriction. This is the plan's permitted exception-preservation restriction, not a claim that cache absence proves there are no exceptions.
- Attendee-bearing, special, locked and conference-bearing resources remain read-only. Standalone projected instances do not acquire ordinary-event write permissions. Known unsupported instance fields are checked from native cached observations, and fresh delivery revalidates current master/instance fields.
- Renderer controls, occurrence gestures and CLI scopes use native availability. Following is disabled with its reason. The editor uses preserve without an exception-reset prompt for Google; local calendars retain reset confirmation. CLI occurrence updates can restore a cancelled selector. Conflict comparison displays individual edits and cancellations.
- Conflict snapshots/review fingerprints retain complete local/observed exceptions. Checked Keep local rebases supported intent onto the observed aggregate, changing only locally edited metadata/occurrence fields and preserving unrelated remote edits/exceptions. Stale reviews fail. Combined master/occurrence and multiple-occurrence replans remain restricted pending phase 03. Keep Google retires the connected pending component and rebuilds observed aggregates.
- Unattempted matching actions cancel through existing atomic group undo. Attempted single-resource undo queues conditional compensation behind predecessor reconciliation. Recreating a delivered deletion reserves a fresh master ID and restores every exception in ordered steps with real instance lookups against that new master. One action counts once; partial restoration retains the complete overlay and resumes forward. Successful remote steps are never automatically rolled back. Attempted multi-step undo and multi-step Keep local remain phase 03 restrictions.

## Schema/API and compatibility

Schema remains v6: existing operation groups, ordering, aggregate snapshots, selectors and reserved resource IDs carry phase 02 intent. No migration or credential/storage change is introduced. Existing v5-to-v6 migration/restart regressions continue to run against pending work. Downgrading to a pre-v6 application remains unsupported.

Generated `EventMutation` adds optional `exceptionPolicy: reset|preserve`. Existing callers omitting it remain compatible: native Google selects preserve, while local native writes retain reset semantics and reject preserve. The pure planner understands preservation; credentials and protocol details stay outside the pure domain. Browser/WASM contracts are regenerated from Rust.

The provider trait gains backend-only instance resolution. Existing providers default to unsupported. Google calendar/event capabilities stored before phase 02 are re-evaluated from native shadows; unobserved pending creates retain editable local overlays. Meeting restrictions are not bypassed by old capability JSON. Previously unsupported cached rules retain their stored projections until refreshed/re-normalized.

## Recovery and remaining restrictions

Restart retains pending groups, reserved resources, selectors, independent instance revisions and incoming shadows; session undo history still ends at restart. Account epoch/lease checks reject late publication/binding. A blocked restoration retains the full intended aggregate while observed steps remain durable. Retry resumes the same ordered steps. Checked Keep Google/calendar discard/account discard publishes retained observations and leaves successfully delivered steps effective; no remote rollback is promised.

Following splits and their explicit future-exception reset, partial-result/replanning UI, attempted multi-step undo and combined conflict replanning belong to phase 03. Structural existing-series edits remain blocked until complete exception correspondence can be proved. Source-zone/DST expansion needs separate equivalence evidence. Meetings/notifications/RSVP, full account removal, special event types, remote moves and conference creation remain outside phase 02. Carry forward everyone/external-only/none notifications with everyone as the future default, and preserve the historical validation boundary.
